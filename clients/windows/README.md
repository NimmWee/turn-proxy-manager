# FreeTurn для Windows

Windows-клиент с привычными экранами FreeTurn Android: вертикальное окно, большая кнопка подключения и пять вкладок снизу. Профили хранятся зашифрованными; VPN запускается только по вашему действию.

Текущая версия — **0.27.0 preview**. Укреплена установка/удаление: сохранённый профиль не передаётся другому пользователю Windows после удаления служб; собственную idle partial-установку можно удалить с проверкой владельца. Расширена экспериментальная поддержка AmneziaWG: диапазоны заголовков/CPS и проверенный набор AWG3-параметров через системный userspace backend; подробности ниже. Постоянная «Блокировка сети» полностью удалена по решению пользователя. После отключения VPN FreeTurn не оставляет самостоятельную блокировку интернета. Экран и команды её включения/выключения удалены; при обновлении снимаются только её устаревшие правила0.23. Получение правил администратора и восстановление сети сохранены. Правила приходят в «Управление доступом → Обновить правила сети» либо вместе с включённой фоновой проверкой подписки; применяются при следующем подключении в системном режиме. Серверные домены/presets/DNS заменяют соответствующие локальные настройки только для данного managed-профиля; локальные EXE-правила сохраняются.

Восстановление сети включается существующим переключателем «Восстанавливать после обрыва, смены сети и сна». Работает только после ручного подключения и пока открыто приложение, максимум5 попыток. Другие VPN не отключает. Сохраняет текущий профиль/ключи/маршрутизацию и выбранный Direct/Relay; новый автоматический бюджет выбора транспорта появляется только при ручном Connect. Старый handshake/egress после восстановления не считается подтверждением нового. Непрерывная блокировка трафика между подключениями не предусмотрена. Фактические смена Wi-Fi, сон/пробуждение и VPN этой версии **NOT RUN**.

В0.22 Добавлены правила для приложений по полному пути EXE: VPN, напрямую или блокировать. Они работают в раздельном режиме; если владелец соединения не подтверждён, трафик блокируется. Добавлено разовое разрешение IPv4-имён `.local` через DNS раздельного маршрутизатора, при включённой локальной сети. Автоматический поиск служб Bonjour не реализован; работа на реальной LAN/Windows ещё не проверена. Для IP-правил раздельной маршрутизации добавлена база геолокации DB-IP Lite за ноябрь2026 вместо данных о регистрации адресов. В настройках видны источник и дата базы этого пакета; геолокация остаётся приблизительной. Обычный WGNT-режим работает по умолчанию, раздельная маршрутизация включается отдельно. Сохранены исправления браузера CAPTCHA, применения настроек и восстановления управления. Проверки сборки выполнены локально; реальное подключение и системная маршрутизация этой версии **NOT RUN**.

## AmneziaWG — экспериментальная поддержка0.26

Импортируется ссылка FreeTurn с WG/AWG-конфигурацией внутри. Для AWG пользователь должен явно включить системную маршрутизацию: приложение не включает её само и не передаёт AWG-параметры обычному WireGuardNT. Исходный текст, ключи и параметры сохраняются в редакторе/DPAPI/зашифрованной резервной копии. Direct/Relay меняет внешний транспорт. Сервер должен действительно поддерживать совместимые параметры AWG; добавление полей в обычный WG-профиль сервера не превращает его в AWG. Managed subscription v1 пока только WG.

Проверенный набор: Jc≤16,Jmin/Jmax≤1280,S1–S3≤512; H1–H4 —непересекающиеся uint32 числа/диапазоны>0; S4+верх ContentPaddingAddition≤64. I1–I5: строгие b/r/rc/rd/t tags,≤12 tags/chain,≤1280 выходных байт/packet,≤4096 chars/chain. Неизвестные/d/ds/dz tags отклоняются. AWG3 HeaderProtectionKey —строго32-byte base64 nonzero key, S1–S4≥12; RandomTrailers/DisableCookies и bounded timers поддерживаются при явном указании. Zero timers используют стандартные defaults. Bounds: rekey30–150s,reject60–180s,retry3–15s,keepalive3–30s,attempts1–20; reject lower должен быть выше rekey upper и суммы keepalive/retry upper. Не все допустимые upstream-параметры входят в это ограниченное подмножество; диапазон Peer PersistentKeepalive пока отклоняется.

Действуют ограничения системного backend: один IPv4 адрес10.77.43.x/32, публичный IPv4 DNS, MTU1280–1420, IPv6 блокируется. Настоящие локальные encrypted TCP/UDP/handshake для WG/AWG1/2/3,1252-byte UDP payload и wrong header key refusal проверены. Реальный AWG сервер/FreeTurn Direct/VK/TUN/egress/leaks/длительные timers/cookies под нагрузкой этой версии ещё NOT RUN. Обычные WG-профили сохраняют прежний режим; ключи/параметры в журнал не выводятся.

## Что уже доступно

- В «Системная маршрутизация → Настроить приложения» можно выбрать EXE и маршрут VPN/напрямую/блокировать (до64 правил). Нажмите «Готово», затем сохраните маршрутизацию; настройки используются после нового подключения в раздельном режиме. Приоритет приложения выше обычных доменных исключений/пресетов; BLOCK и служебная защита сохраняются. Без правил определения процессов нет. При наличии правил непроверенный или неоднозначный владелец data flow блокируется. DNS53 остаётся общим, в том числе при BLOCK приложения. Отдельный сетевой helper EXE требует своего правила; пути сравниваются без учёта регистра. Это путь, не проверка подписи/содержимого файла и не sandbox. Windows owner tables являются снимками, а переданные между процессами socket handles могут сохранять первоначальный PID-владелец. UDP повторно проверяется перед send/delivery; нагрузку этого механизма нужно измерить. Paths не выводятся в логи/status, настройки входят в DPAPI/encrypted backup. Старые версии могут отказаться читать backup с новыми непустыми appRules; для downgrade сначала удалите правила в новой версии и сохраните настройки либо используйте старый backup. Реальное app/TUN/WFP/UDP/performance E2E **NOT RUN**.

- При включённом «Локальная сеть напрямую» DNS-маршрутизатор может разрешать A-имена `nas.local`/`printer.local` через разовый mDNS-запрос в выбранной домашней подсети. Локальный DNS-сервер для этого не нужен. Ответ принимается только с того же сетевого интерфейса и из той же частной подсети; имя не отправляется публичным DNS и не сохраняется в истории. При ошибке возвращается отказ, без публичного fallback. IPv6/link-local169.254, публично адресованные LAN и DNS-SD/PTR/SRV browsing здесь не поддерживаются. Программы с собственным native5353/Bonjour discovery могут обходить этот DNS-путь: общий Windows поиск устройств и реальная LAN/VPN совместимость **NOT RUN**. При обычном WGNT-режиме это расширение не используется.

- IP-правила «Российские сайты напрямую» используют закреплённый снимок DB-IP Lite2026-11:12 902 IPv4-диапазона RU. YouTube, push, явные правила и защита служебных адресов сохраняют свой приоритет. Неизвестные IP остаются на VPN; ошибки базы или DNS не разрешают произвольный прямой выход. База входит в пакет и не обновляется фоновыми сетевыми запросами. Новые данные начинают использоваться после обновления ядра и нового подключения. Источник: [IP Geolocation by DB-IP](https://db-ip.com/), [CC BY4.0](https://creativecommons.org/licenses/by/4.0/). Включены атрибуция, описание преобразования и исходные данные. Это приблизительная оценка страны, не гарантия обхода VPN-проверок сайтов.

- Браузер CAPTCHA работает внутри главного окна без composition-захвата D3DImage, в финализаторе которого Windows зафиксировала падение0.18. Автоматический режим скрыт, ручной виден в том же приложении. Закрытие во время запуска отменяет дальнейшую инициализацию. Проверены повторные локальные открытия/закрытия и сборка мусора; длительная реальная проверка VK/VPN этой версии ещё нужна.

- Если ответ активации потерялся, откройте «Управление доступом» при подключённом VPN и повторите проверку. После истечения стартового доступа кнопка называется «Проверить восстановление». Если сервер принял прежний запрос, управление восстановится с тем же токеном и ключами. Если запрос не был принят и срок истёк, потребуется администратор. При смене соединения или ошибке сервера данные сохраняются; новое устройство автоматически не создаётся.

- После «Серверы → Параметры → Сохранить» выбранный профиль остаётся выбранным. При следующем подключении ядро получает новые значения. Если старая версия уже сняла выбор, выберите сервер один раз: при непустом каталоге старая копия службы автоматически не используется. Сохранение не перестраивает активный VPN. В главном окне видны фактические лимиты потоков, в подсказке/журнале — безопасные параметры DNS/MTU/CAPTCHA. В автоматическом Direct один поток является нормой, Relay использует указанное в профиле количество. Режим DNS редактора относится к служебным запросам FreeTurn; DNS трафика VPN задаётся в WireGuard Interface. Неверные значения показывают сообщение возле кнопки сохранения.
- В «Настройки → Приложение → Транспорт» включается автоматический выбор Direct / Relay. По умолчанию выключен. Требуется WireGuard-профиль с VK-ссылкой: canonical URI, CID, WG/OBF keys и endpoint не меняются. При следующем ручном подключении сначала проверяется Direct (30с), затем Relay (60с), максимум два переключения на попытку. Рабочий путь сохраняется без периодического перебора. CAPTCHA и длительный sleep приостанавливают таймер; auth/rate-limit, ручное действие или другой сеанс останавливают автоматику. Перезапускается только FreeTurn proxy, адаптер/маршруты/DNS не перестраиваются. Пока приложение закрыто, новые переключения не выбираются; startup/backup не восстанавливают connect intent. Сетевой эффект и отсутствие утечек новой версии ещё требуют реальной проверки.
- Подтверждённая рабочая managed-конфигурация хранится зашифрованной вместе с профилем и входит в backup. Нужны устойчивые минимум5 секунд handshake и подтверждённый службой выход в интернет. После ручного выбора обновления и ручного подключения ядро0.16 выдаёт номер попытки. При ошибке этой попытки или120 секундах неподтверждённого соединения приложение может один раз вернуться к сохранённой конфигурации, сохранив неудачное обновление и ключи. CAPTCHA/длительный sleep не расходуют таймер; auth/rate-limit ошибки, отзыв доступа, ручное отключение или другой сеанс запрещают возврат. UAC/установка служб при возврате не вызываются. Перезапуск приложения не возобновляет попытку. Ошибки подготовки до принятого Connect требуют ручного действия. Старую конфигурацию сервер всё ещё должен принимать; повторное подключение само по себе не подтверждает интернет. При включённом автоматическом транспорте сначала проверяются пути; возврат профиля ждёт завершения этих попыток. Рабочий path сохраняется вместе с LKG.
- В «Настройки → Приложение» можно включить проверку обновлений управляемого профиля. По умолчанию выключена. Нужны зарегистрированный managed-профиль и подтверждённое подключение ядра 0.15 или новее; выбранная строка списка не определяет работающий профиль. Пока приложение открыто, проверка идёт через 15 секунд и затем раз в 30 минут, через внутренний HTTPS API. При ошибках запрос откладывается. Candidate сохраняется отдельно и применяется по вашему решению; VPN не переподключается автоматически. При подтверждённом 401/403 доступ блокируется, служба получает команду остановить только соответствующее соединение. После закрытия приложения проверок нет; отдельная фоновая служба подписки ещё не реализована.
- Каталог подключений: импорт `freeturn://` и файла, выбор, редактирование, переименование, копирование и удаление. Сохранение и выбор не требуют установленной службы; профиль применяется при подключении.
- Постоянный доступ `ftm-enrollment` из панели: откройте JSON или вставьте ссылку `ftm-enroll://…` на вкладке «Добавить», задайте имя компьютера и нажмите «Начать регистрацию». До HTTPS-запроса ключи, Client ID, token и UUID запроса сохраняются в DPAPI. После сбоя или перезапуска продолжите в «Добавить → Незавершённые регистрации»: новые ключи и второе устройство не создаются. Готовый профиль добавляется в каталог, затем выбирается и подключается вручную.
- Регистрация использует публичный HTTPS-адрес из подписки. По явному выбору можно использовать уже подключённый FreeTurn и внутренний API с той же TLS identity; автоматического переключения нет. Если публичный HTTPS недоступен и рабочего VPN нет, используйте персональный стартовый JSON. Токены передаются только Authorization-заголовком, без HTTP query/path. Локальная ссылка — обёртка существующего JSON, а не новый серверный endpoint; запуск приложения из браузера пока не зарегистрирован в ОС.
- После подтверждения регистрации user token удаляется из текущей попытки; device token и private key сохраняются. Потерянный ответ проверяется через device credential перед повтором POST. Pending попытки входят в зашифрованную копию; конфликт identity не заменяет существующие ключи. Старые backup/.previous могут содержать прежнее encrypted состояние. Metadata регистрации требует0.14+, обычные профили сохраняют прежний формат.
- Персональный `ftm-bootstrap` JSON из панели: откройте файл на вкладке «Добавить», проверьте и добавьте сервер. После обычного подключения откройте «Серверы → Управление → Активировать управление». Проверяется соответствие ключа/устройства/адреса; credential сохраняется в DPAPI до отправки, повтор не меняет его. HTTPS идёт только к API внутри VPN с проверкой публичного TLS имени. Истечение срока активации не отключает сам VPN.
- В «Управлении» кнопка «Проверить обновление» получает подписку через VPN. Устройство, ключ, origin, revision и ETag проверяются до записи. Обновление хранится отдельно; кнопка «Использовать при следующем подключении» меняет только каталог. Для его использования переподключитесь вручную. «Вернуть предыдущий профиль» возвращает локальную копию; сервер должен продолжать принимать старые параметры. Ваш private key и credential не меняются. Отказ доступа блокирует последующие подключения выбранного managed-профиля и применение старых обновлений; ключи не удаляются. Серверный отзыв активного peer обеспечивает сервер, клиент не останавливает вслепую другое открытое подключение.
- Обновления пока проверяются вручную. Периодическая синхронизация, подтверждённый трафиком автоматический LKG/rollback и Direct↔Relay Connection Manager ещё готовятся. Старые preview не читают новые поля managed-каталога.
- Экспериментальная системная маршрутизация включается отдельно в настройках. Локальные имена (`printer`, `nas.home.arpa`, `.lan`, `.home`, `.internal`, `.corp`, `.intranet`, `.test`) используют только настроенный DNS физической локальной сети; публичного fallback нет. Нужен private IPv4 DNS в подключённой подсети и включённое правило локальной сети. При отсутствии такого DNS используйте IPv4-адрес устройства. `.local`/mDNS пока не поддерживается. Private DNS возвращает реальные локальные IPv4; доменные ограничения не заменяют запрет доступа по самому IP.
- Долговременный fake-IP cache хранит keyed HMAC→IP под AES-GCM/DPAPI, без hostname, URL или времени посещений. При обновлении формат0.10 мигрирует без смены IP/ключа. Старый IP из cache приложения восстанавливается по свежему DNS либо совпавшему TLS SNI/HTTP Host; неизвестный UDP, ECH или протокол без имени может потребовать перезапуска приложения. Данные TLS не расшифровываются и не записываются.
- Передача профиля текстовой ссылкой или файлом; вставка ссылки из буфера обмена. QR и камера исключены из Windows-клиента по решению пользователя.
- Резервные копии под паролем: все профили, ключи, SSH-настройки и настройки окна. Восстановление добавляет записи к существующим и не включает VPN. Есть импорт зашифрованного Android backup v4 с сохранением истории исходных документов; неподдерживаемые режимы не применяются автоматически. Нужный исходный Android backup можно выгрузить отдельно, без включения последующих Windows-правок.
- Обычный WireGuard через VK Relay или Direct, транспорт до TURN TCP/UDP, профили обфускации none/rtpopus/rtpopus2/rtpopus3. Настройки должны соответствовать серверу.
- Отдельный TCP/UDP-проброс на `127.0.0.1`, KCP/Bond для TCP. Он не включает системный VPN. С WG используется UDP и listener `127.0.0.1:9000`; для отдельного проброса WG-конфигурация должна быть пустой.
- Локальный SOCKS5 TCP CONNECT: логин/пароль обязательны, default — VPN. До300 доменных правил «Напрямую / Через VPN / Блокировать» с поддоменами или точным совпадением. BLOCK выше разрешений; остальное — наиболее точное правило. DNS следует выбранному пути: VPN DNS через WG, DIRECT через IPv4/DNS физической сети. Соединения привязаны к своим LUID/source, без перехода на другой путь при ошибке. Без UDP, IPv6, private/LAN destinations и раздачи в LAN. Нужен подтверждённый VPN; при его потере весь прокси останавливается. Реальный SOCKS egress пока NOT RUN.
- SSH-настройки по каждому серверу: пароль или приватный ключ, закрепление SHA256 host key и проверка аутентификации. Неизвестный/изменённый ключ останавливает вход до отправки пароля. Команды и установка на VPS этой проверкой не выполняются.
- Трей, автозапуск окна при входе в Windows по выбору, ограниченное переподключение после ручного запуска. До пяти повторов с задержкой; «Отключить», импорт и смена профиля отменяют повторы. Запуск приложения и восстановление копии сами VPN не включают.
- Тёмная/светлая тема (переключение после перезапуска), безопасный журнал, счётчики/скорость/время и число потоков, информация о версии и лицензиях.

Продвинутая CAPTCHA использует штатный экспериментальный browser PoW с прежней автоматикой при неудаче. По умолчанию выключена; ручной режим имеет приоритет. В Windows используется WebView2 Runtime, который устанавливается отдельно. Полное отсутствие CAPTCHA не обещается.

## Запуск и обновление

1. Распакуйте весь архив, закройте старое окно и запустите `FreeTurn.Windows.exe` обычным пользователем. Нужна Windows10 x64 версии1809 или новее / Windows11.
2. Добавьте отдельный Windows-профиль на вкладке «Добавить». После сохранения откроется главная страница с выбранным сервером. Существующий профиль можно использовать повторно; новые ключи не требуются.
3. Нажмите «Подключить». FreeTurn проверит совместимость установленного ядра и при необходимости подготовит его из текущего пакета. Подтвердите UAC, если его запросит Windows. При актуальном ядре обновление и запрос прав пропускаются. Отмена или ошибка останавливают цепочку до подключения; старшая версия установленного ядра не понижается.
4. Выбранный профиль применяется автоматически, затем запускается соединение. Прежний профиль, сохранённый только службой, остаётся доступен. Сначала вручную отключите другой VPN: FreeTurn его не останавливает.
5. Состояние и этапы видны на главной; подробности — во вкладке «Логи». Большая кнопка с подписью отменяет попытку или отключает VPN. Ctrl+Enter выполняет основное действие; Ctrl+1…5 меняют вкладки, Alt+← возвращает из вложенного раздела.

Установка/обновление используют прежний guarded setup: только собственные службы, остановленный tunnel, тот же владелец; при неудаче замены/старта — попытка rollback. Ключи и профиль обновление не переписывает. Во время работающего VPN ядро не меняется. Фоновое переподключение не вызывает UAC: если нужно обновление, требуется ручное нажатие «Подключить». Ручное «Восстановить ядро» остаётся в продвинутых настройках как средство ремонта. Автоматического скачивания новых релизов из интернета пока нет.

Разделы открываются внутри окна с «Назад» и сохранённой нижней навигацией. Только штатный выбор файлов, UAC и подтверждения остаются системными диалогами. Автоматическая CAPTCHA работает в невидимом встроенном браузере, ручная проверка появляется в том же окне; WebView2 Runtime требуется отдельно.

Доменные правила доступны в «Настройки → Продвинутые → SOCKS5 → Маршрутизация SOCKS5». Введите домен без URL/порта, выберите действие и поддомены, добавьте правило, затем сохраните. Есть поиск, редактирование, удаление и локальная проверка маршрута без DNS. Для применения остановите и заново запустите SOCKS5. Нужны службы0.6+: старая служба не получит правила молча. В использующей прокси программе включите DNS через SOCKS5 (`socks5h`): если программа заранее прислала IP, домен определить невозможно и действует VPN default. Правила и пароль входят в encrypted backup; сохранение не запускает сеть.

Это отдельные правила SOCKS5 TCP/IPv4. DIRECT раскрывает выбранному сайту обычный IP, а имя — выбранному DNS прямого маршрута. Не обещается устранение всех сообщений о наличии VPN.

## Экспериментальная системная маршрутизация

В расширенных настройках откройте «Системная маршрутизация». Включите режим, выберите presets, при необходимости добавьте доменные исключения и сохраните. Проверка и сохранение работают локально; правила применяются только после нового подключения. До этого обычный VPN продолжает работать по прежним настройкам. Служба обновляется штатным подготовительным шагом при подключении; отдельно устанавливать второй VPN-клиент не нужно.

- Российские домены и домашние IPv4-устройства — напрямую; YouTube/push — через VPN; connectivity checks — напрямую. BLOCK и защищённый адрес управления сервером выше обходов; явные доменные исключения выше пресетов. Остальное — VPN, без прямого fallback при ошибке.
- Раздельный DNS следует выбранному маршруту. По умолчанию DIRECT использует Яндекс (IPv4 DNS/53), VPN — DNS из WG-профиля. До четырёх прямых DNS-адресов можно изменить в окне. Private names/mDNS и private WG DNS пока не поддерживаются; имена локальной сети не отправляются публичным resolver.
- Режим IPv4; IPv6 блокируется. Российские IP определяются по закреплённому RIR allocation snapshot, это не точный GeoIP. Собственный DoH/DoT приложения и IP literals могут скрыть имя; доменные приоритеты тогда не гарантируются. BitTorrent block распознаёт известный plaintext/DHT, не любое шифрование.
- Текущий профиль должен использовать baseline-сеть10.77.43.0/24 и public IPv4 WG DNS. Иначе подключение этого режима отклоняется до запуска службы. Отдельный SOCKS5 вместе с ним пока недоступен.
- Защита маршрутов действует, пока работает служба. Постоянный OS network lock при crash/boot ещё не реализован и не заявляется проверенным kill switch.
- Окно показывает отдельно сохранённый выбор и фактическое состояние службы/потоки. Настройки входят в зашифрованный backup. Выключение режима также применяется при следующем подключении; приложениям с собственным DNS-кэшем после смены режима может понадобиться перезапуск.

Стабильные fake-IP идентификаторы сохраняются только службой в encrypted append-only журнале ProgramData. AES-256-GCM key защищён SYSTEM DPAPI; записи и отдельный high-water mark синхронизируются до DNS-ответа. Между сессиями сохраняется соответствие имени и идентификатора, а решения/реальные IP разрешаются заново. Пул ограничен131066 именами/64MiB; нет автоматического переиспользования адресов или сброса повреждённой истории. Не удаляйте эти служебные файлы ради «очистки»; при повреждении используйте обычный WGNT-режим до восстановления. User backup не переносит историю посещённых DNS-имён и не очищает её на текущем ПК.

Новая сборка читает прежние локальные каталоги. Старые preview могут не понимать новые настройки и откажутся писать поверх них; перед откатом сохраните зашифрованную копию.

## Что ещё не завершено

AmneziaWG extensions требуют отдельной приёмки: обычный WireGuardNT их не исполняет, а наличие userspace WG не доказывает AWG-паритет. Для системного маршрутизатора остаются private names/mDNS, точный GeoIP, app matching, policy delivery и настоящие OS/leak/recovery проверки. Также открыты управление сервером/доступами из приложения, managed-подписки/bootstrap и автоматический Direct↔Relay fallback, LAN hotspot, UDP/IPv6 SOCKS, latency meter, остальные языки/privacy/system-theme settings, подписанный installer и online updater. QR исключён пользователем. Сохранённые Android-настройки не считаются работающим Windows backend.

Реальные проверки подключения, утечек DNS/IPv6, sleep/resume, смены сети и cleanup на чистой Windows10/11 остаются открытыми. Внешнее сходство не означает полный функциональный паритет: native Windows titlebar/dialogs сохранены, контуры expressive-кнопки адаптированы для WPF без точного Android morph-движка.

## Сборка и локальные проверки

Нужны Windows x64, .NET SDK8+, Go1.27.3+, Python3.10+. NuGet-пакеты и Go-модули закреплены lock-файлами. Для дополнительной локальной SSH-проверки нужен Python Paramiko; сервер создаётся только на loopback с синтетическими ключами.

```powershell
./clients/windows/build.ps1 -GoExecutable "C:/path/to/go.exe"
dotnet run --project clients/windows/catalog-check/CatalogCheck.csproj -c Release
python clients/windows/verify_ssh_loopback.py
pwsh -NoProfile -File clients/windows/verify_service.ps1
pwsh -NoProfile -File clients/windows/verify_offline.ps1
```

`prepare.py` сверяет SHA256 исходников/драйвера; сборка проверяет подпись официального WireGuardNT и SHA256 встроенных шрифтов, выполняет Go test/vet, публикует self-contained UI и упаковывает только перечисленные файлы. Она не устанавливает службы и не меняет сеть. `--check-single-window` проходит встроенные формы и проверяет локальный WebView2 без VK/VPN. `--check-desktop-ui` проверяет регистрацию/удаление значка, скрытие/показ своего тестового окна и встроенный Roboto с кириллицей. Offline snapshot-режимы используют синтетические данные. Тема, параметры окна и резервные копии находятся в «Настройки → Приложение».

Пакет включает соответствующие исходники, dependency notices, SHA256SUMS и лицензии. Собственные EXE не подписаны; драйвер — официальный подписанный WireGuardNT. Исходный Android5.3.4 и его GPL-3.0 attribution сохранены, серверный baseline не изменён.

## Журнал и отзывчивость0.9

Журнал показывает время до миллисекунд, INFO/WARN/ERROR, номер потока и безопасное описание событий DNS/VK/CAPTCHA/TURN. Есть поиск, фильтр уровней, автопрокрутка и экспорт. Неизвестный raw текст не экспортируется: URL, ключи и credentials исключены. Служба сохраняет последние128 структурированных событий в SYSTEM DPAPI; UI удерживает до1000 строк. «Очистить» очищает экран, не runtime history службы.

Опрос —250мс при установке соединения,500мс при рабочем VPN и3с в простое; часы окна обновляются локально каждые250мс. Записи runtime объединяются, при отсутствии новых событий не выполняются четыре одинаковые записи в секунду. Это сокращает задержку отображения; увеличение пропускной способности VPN не измерено. Во время активного подключения крестик скрывает приложение в трей; полный выход — «Выйти» в меню трея.
