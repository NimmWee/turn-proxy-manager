# Нижняя навигация Windows, как в Android

15.11.2026. Нижняя навигация перенесена в0.2.1 preview. По следующему поручению пользователя в0.3.0 окно стало вертикальным по умолчанию, без изменения установленного VPN.

## Исходник и расположение

Проверен Android5.3.4 commit `bab60c5fb620cbea2570eeeb5a0697dc355071f4`, `ui/navigation/AppNavigation.kt`. Порядок: **Главная → Логи → Поделиться → Настройки → Добавить**. В исходнике Логи опциональны, но пользователь показал вариант с пятью кнопками; Windows отображает все пять.

Использованы оригинальные Android vector paths: `home_24px`, `home_outlined_24px`, `terminal_24px`, `share_24px`, `share_outlined_24px`, `settings_24px`, `settings_outlined_24px`, `add_24px`. Также перенесены `play_arrow_24px`/`stop_24px`. Генератор `clients/windows/import_android_icons.py` закрепляет commit, проверяет viewport960×960 и сохраняет fill rule. Полученные Geometry resources включены в сборку; отдельные шрифты с псевдоиконками не нужны. GPL attribution сохраняется.

Левая панель убрана. Панель навигации закреплена снизу, не участвует в прокрутке. Выбор сервера закреплён над ней только на главной, как нижний серверный блок Android. Активная вкладка имеет цветную капсулу и filled icon; остальные используют исходные outlined icons.

## Адаптация к Windows

- Значки24 DIP, область кнопки минимум68×68 DIP, подписи12 DIP. При ширине420 все пять кнопок доступны.
- Окно по умолчанию480×860 DIP, минимальная ширина420. Высота ограничена рабочей областью экрана. Панель центрирована, max width760; при расширении окна кнопки не разъезжаются по всей ширине экрана.
- Страницы и список серверов прокручиваются; ряды действий переносятся при нехватке ширины. Редактор подключения тоже вертикальный, с закреплёнными кнопками сохранения/отмены.
- Подсказки мыши, hover/pressed feedback, видимая клавиатурная рамка.
- Ctrl+1…5 переключают соответствующие вкладки. Стрелки в панели переходят между вкладками; Tab останавливается на выбранной кнопке и затем идёт в содержимое.
- Выбор сервера доступен на Главной и в Настройках.
- «Логи» показывает ограниченный журнал фиксированных безопасных событий приложения с очисткой/экспортом. Raw core/SSH logs, профили, exception strings и токены туда не направляются.
- «Поделиться» позволяет явно скопировать или сохранить собственный профиль из пользовательского каталога. Это копия того же устройства, **не** выдача нового независимого peer; создание доступа/QR остаётся в полном плане переноса. В интерфейсе различие явно обозначено.

## Проверки

WPF build/publish PASS, без предупреждений. В0.3.0 просмотрены offline renders главной480/420 DIP, Добавить, Настройки, Логи, Поделиться и редактора, включая узкие формы420: все пять кнопок видимы, подписи не обрезаны, выбранная иконка меняется. Длинный флажок и ряды кнопок переносятся, редактор прокручивается; системные действия в preview отключены. Результат обычного Tab ниже исторический, в0.3.0 заново не подтверждался.

Настоящее офлайн-окно: click Настройки, Ctrl+5→Добавить, Ctrl+2→Логи, Ctrl+3→Поделиться и ArrowRight→Настройки **PASS**. После Ctrl+3 фокус находится на выбранной кнопке Поделиться, после стрелки — на Настройках. Обнаруженное несовпадение focus/selection после shortcut исправлено: shortcut фокусирует выбранную кнопку; в Tab-order включена только она.

Конечный фокус после Tab **NOT RUN/не подтверждён**: инструмент Windows capture вернул `no monitor found for window`, затем `foreground window did not report a process id`. Процесс preview при этом оставался Responding, новых .NET/Application Error crash events не было. Это не объявлено ошибкой/успехом программы. После повторного сбоя прекращены UI inputs; перед пересборкой отдельно подтверждено, что созданный offline preview больше не запущен. Стандартный Tab traversal реализован, но его итог не приписывается успешно выполненному сценарию.

Эти проверки касаются интерфейса; они не являются новым VPN/CAPTCHA E2E. Preview не вызывает службу/не подключает туннель. Установленные Desktop0.1.1 и SYSTEM service не заменялись.
