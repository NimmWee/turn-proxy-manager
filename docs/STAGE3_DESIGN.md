# Первая рабочая панель

Реализуется по уже согласованному ТЗ и ночному поручению без ожидания ответов пользователя. Применены brainstorming и writing-plans; новые необязательные пожелания пользователя ночью не запрашиваются. Работа без субагентов. Полного автотестового покрытия не требуется.

## Выбранный вариант

Rootless FastAPI под `ftm-api` и статический React/Vite/Tailwind. API работает только с ограниченным Unix RPC, не открывает root SQLite и ключевые файлы. Это продолжает проверенную IPC-модель. Прямой root API или передача ему metadata DB исключены требованиями безопасности. Один backend process и статические assets подходят небольшому VPS; Node используется только для локальной сборки.

Пока нет домена или доверенного IP-сертификата, слушать только loopback и давать доступ через SSH port forwarding. Публичные 80/443 не открывать автоматически. Caddy/domain/TLS остаются отдельной конфигурацией следующего блока; нельзя выдавать private HTTP через SSH за проверенный public HTTPS.

## Авторизация

Случайный путь `/a/<random>/`, вход по имени/паролю администратора, rate limiting. Password hash scrypt, root-owned private web config с ограниченным чтением сервису API. Пароль выдаётся отдельно в root-only private файле, никогда не попадает в Git или журналы. Сессии — случайные opaque cookies, server-side in-memory storage, TTL, logout удаляет сессию; после restart требуется новый вход. HttpOnly, SameSite=Strict; Secure обязательно в HTTPS-режиме, в loopback SSH-only режиме cookie может работать по локальному HTTP.

Все операции изменения требуют активную сессию, CSRF header и проверку Origin. Ограничить размер body, схемы/типы и число активных сессий. Неправильный panel path и неавторизованные запросы не раскрывают данные. Не включать OpenAPI/Swagger публично. Чувствительные запросы не логировать. Бэкап из UI и re-auth trigger пока не включать до безопасного export-контракта.

## Интерфейс и данные

Русская адаптивная панель: боковая навигация, обзор состояния и ресурсов, таблицы пользователей/устройств, понятные empty/error/loading states, поиск, создание пользователя, отключение и повторное включение устройства с подтверждением. Светлая и тёмная темы; контрастные статусы, спокойный синий акцент, без внешних шрифтов/CDN. На мобильном карточки и доступная навигация. На `/` нейтральная заглушка.

CPU/RAM/traffic/handshakes только из настоящего сервера, метрики через новый ограниченный RPC. Первый CPU sample может быть неизвестен — показать ожидание, не выдумывать ноль. Traffic — счётчики текущего WG interface, не обещать месячный учёт. Недавний handshake — оценка активности, не доказательство E2E. Direct/Auto/subscriptions/bootstrap не изображать готовыми.

Добавление устройства на данном шаге использует клиентский public key; UI не генерирует сервером личный private key и не обещает готовый enrollment до этапа 4. CRUD и статусы доступны, секреты CID/PSK не входят в обычные списки.

## Проверка

Целевые проверки auth/CSRF/logout/unauthorized mutation, затем реальный login и CRUD через API к установленному Unix service. UI — production build и браузерная проверка desktop/mobile/light/dark, без теста каждого компонента. Перед deploy — свежий offsite checkpoint. Измерить реальные процессы/память и сохранить профиль iPhone. Тесты устройств и публичного TLS остаются NOT RUN до доступного стенда.

Зависимости закреплять по доступным официальным registry и lock-файлам. Источники: [FastAPI version pinning](https://fastapi.tiangolo.com/deployment/versions/), [React versions](https://react.dev/versions), [Vite requirements](https://vite.dev/guide/).
