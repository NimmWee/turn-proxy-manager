По последующему поручению пользователя выполнены только разрешённые локальные тесты: полный DTLS/rtpopus3/Direct/TURN TCP/UDP стенд,N1/2/4/6/8,90 paced+36 overload фаз и CPU/alloc profiles. Пакеты при10/50/100Mbps переданы без потерь; перегрузочные потери зафиксированы, причина дальше core очереди пока не локализована. Проверен временный single-copy Pion candidate (7.79% меньше alloc при равных100Mbps, устойчивое ускорение не доказано); поставляемый core не менялся. Остались реальные Direct/VK/WGNT/system/VPS замеры, выбор/интеграция подтверждённых оптимизаций и живое сравнение. [Стенд/данные](CORE_LOCAL_BENCHMARKS.md). Следующие абзацы — исходное отложенное поручение, а не запрет уже разрешённых измерений.

Пользователь попросил вернуться к увеличению скорости после завершения текущего согласованного технического объёма. Сейчас оптимизацию ядра/параметров не начинать и порядок основных задач не менять. При необходимости позже сравнить предоставленное пользователем ядро с закреплённой локальной версией.

Начать с воспроизводимых замеров: Direct и VK Relay отдельно, загрузка CPU/RAM клиента и VPS, пропускная способность/задержка/потери, влияние числа потоков и повторной авторизации. По результатам установить узкое место: клиентское ядро, транспорт/TURN, канал или ограничения VPS. Менять один фактор за раз и сравнивать с исходным результатом. Не обещать конкретный прирост до измерений, не повышать лимиты и не запускать фоновые speed tests автоматически. Сохранять рабочие ключи/профили, совместимость и приемлемую нагрузку; результаты отличать от синтетических проверок.
