# Тест базового VPN на iPhone

Дата: 10.11.2026, Asia/Tomsk. Пользователь разрешил установку на отдельном тестовом VPS и передал VK call link. В Git эта ссылка и импортируемые профили не сохраняются.

## Развёртывание

На тестовом VPS Ubuntu 24.04.4, 1 vCPU / 961 MiB RAM установлены WireGuard tools, iptables/nftables, qrencode и закреплённый FreeTurn 4.1.2-vps1.

`ftm/baseline_deploy.py` проверяет SHA256 сохранённых файлов и запускает исходный Vps через его существующий entrypoint с единственным переопределением: hook `configure_fail2ban()` использует годовую политику Manager. `vendor/vps/` не менялся, существующий CLI `vps-vk status/profiles/backup` сохранён. Это базовый VPN, не готовый полный Manager.

Команда (только согласованный тестовый VPS; VK URL находится в отдельном root-only файле):

```bash
python3 -m ftm.baseline_deploy --apply --vk-link-file /root/ftm-vk-link --endpoint АДРЕС_ТЕСТОВОГО_VPS --qr
```

Пакеты предварительно устанавливаются из Ubuntu apt. Не использовать исходный установщик напрямую для повторной настройки Fail2ban: он ожидает старую политику 30 дней.

## Подтверждено на сервере

- Первая установка завершилась успешно; созданы независимые baseline peers iPhone/Android.
- Повторная установка сохранила **всё состояние VPN**, включая ключи/CID/VK link/endpoint/подсеть. Сравнивались сериализованные состояния, секреты не печатались.
- `vps-vk status`: FreeTurn, network unit и Fail2ban **active**, peers **2**, NRestarts **0**, Result **success**.
- SSH сохранил MainPID **712**, NRestarts **0**. Новое SSH-подключение после установки проверено успешно.
- Fail2ban: maxretry **3**, findtime **600**, bantime **31536000**.
- Внешний WireGuard backend UDP/51830 закрыт scoped правилом INPUT DROP; FreeTurn принимает UDP/56001. Сброс firewall не выполнялся.
- iPhone import text и QR имеют режим **0600**. Пользовательская ссылка VK также хранится root-only.
- Создан зашифрованный baseline backup и скачан вне VPS. Decrypt/parse с реальным состоянием проверен на сервере и локально; ключ в backup совпадает с выданным iPhone-профилем. Recovery file находится вне Git рядом с приватными пользовательскими артефактами. Чистое системное восстановление на другом хосте **не проверялось**.
- Одноразовый замер MemoryCurrent FreeTurn после запуска: **2297856 байт**. Это idle-замер без клиентского трафика, не проверка производительности.
- Локальные tests: **41 Manager + 8 baseline**, без пропусков в Ubuntu WSL; новый deployment adapter отдельно проверен и на VPS.
- После установки полный Manager-набор на VPS: **41/41 PASS**. CLI regression test использует явное синтетическое состояние, чтобы не зависеть от наличия настоящего VPN на хосте.
- Перед выдачей профиля зарегистрированы 2 peers, свежих handshake пока **0**: пользовательский iPhone-тест ещё не начат.

Приватные артефакты для пользователя передаются отдельно, вне workspace Git. Профиль iPhone содержит персональный ключ, PSK, Client ID и параметры VK; их не нужно вставлять в отчёт об ошибке.

## Проверка пользователем

1. В установленном приложении Anton48 сохранить текущие настройки: **Settings → Export Full Backup**.
2. Скопировать полное содержимое выданного `iPhone-import.txt` и выбрать **Settings → Import from connection link** (в исходной документации подпись `Import from conection link`). Альтернатива — выданный QR, содержащий ту же ссылку.
3. Подключиться, разрешить VPN-конфигурацию iOS, если система спросит. Если приложение запросит VK CAPTCHA/авторизацию, завершить её в приложении.
4. Открыть Safari и проверить несколько HTTPS-сайтов и внешний IPv4: он должен совпадать с адресом тестового VPS. Проверить отдельно Wi-Fi и мобильную сеть, если обе доступны.
5. Сообщить результат; при ошибке — текст ошибки и выбранный режим, без ключей/ссылки импорта. На сервере сопоставить результат со свежим handshake и rx/tx.

## Границы результата

Пользователь **подтвердил** корректное подключение iPhone, работу интернета и ожидаемый внешний IP. На VPS подтверждены свежий handshake и реальные rx/tx. После теста recovery наблюдались повторный handshake и трафик с тем же профилем. Подробности и точные границы — в [отчёте следующего шага](STAGE2_PROGRESS.md).

Пользователь сообщил, что раньше Android из исходного репозитория работал. Это историческое наблюдение, а не новый E2E-тест текущей установки. Даже после успеха iPhone результат Android останется **NOT RUN**, пока его отдельно не проверят. Auto Direct/Relay, подписки и Manager UI здесь не реализованы.
