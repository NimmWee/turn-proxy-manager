# Windows после подтверждения VPN: устойчивость, журнал и уборка

16.11.2026. Пользователь подтвердил успешное реальное подключение0.8.0; сообщил самопроизвольный запрос «Отключить VPN и закрыть FreeTurn?» во время подключения. Разрешил полностью пересмотреть дизайн/навигацию, примеры ещё подбирает. Новое VPN-подключение агент не запускает, работающий туннель не останавливает.

1. Сначала исследовать источник закрытия; код не показывает этот dialog вне Window.Closing. Добавить учёт источника native close/tray/programmatic, целевую политику: посторонний запрос не прерывает подключение; крестик при активном VPN скрывает окно в доступный трей; явный Выход подтверждает отключение. Не объявлять источник самопроизвольного события установленным без воспроизведения. Проверить native сценарий без реального VPN.
2. Перенести больше диагностических событий upstream OnLog/OnState в ограниченный структурированный журнал: timestamp/level/stream/codes/counts. Raw logs/URL/credentials/keys не сохранять и не передавать. Ring+sequence/session, отображение уровней, поиск, export и контроль памяти. Privacy и IPC size — целевые проверки.
3. Убрать фиксированную двухсекундную задержку: адаптивное чтение состояния и локальное обновление часов, coalesced runtime writes. Это отзывчивость интерфейса, не доказанное ускорение VPN. Не менять рабочие transport/MTU/ключи без измерений.
4. Добавить настоящую Windows EXE/window/tray иконку на основе существующего vector logo; новый полный визуальный стиль оставить до пользовательских примеров. Записать очередь UX/иконки/настройки/скорость и первичные ориентиры Proton/Mullvad/Microsoft.
5. Уборка по инвентаризации: убрать воспроизводимые bin/obj/pycache/временные результаты; старые ZIP сохранить. Лицензии/lockfiles/recovery docs/vendor/приватные рабочие данные не удалять. Исторические отчёты можно аккуратно перенести в архив с обновлением ссылок, актуальные документы оставить. Перед recursive delete/move проверить абсолютные цели, исключить reparse points и внешние пути. Отчёт об объёме и списке операций.
6. Собрать отдельный preview, выполнить сборку и целевые privacy/close/native проверки, проверить источник/архив. Зафиксировать user-confirmed VPN отдельно от NOT RUN нового build, сетевых benchmarks, UAC и аппаратных сценариев. После стабильности следующим по ТЗ идёт общесистемный routing; проектирование/независимые шаги не должны менять текущий работающий VPN.

UX-ориентиры: [Proton Windows](https://protonvpn.com/support/protonvpn-windows-vpn-application), [Mullvad desktop](https://mullvad.net/en/help/using-mullvad-vpn-app), [Microsoft app icons](https://learn.microsoft.com/en-us/windows/apps/design/iconography/app-icon-design). Новый дизайн должен сделать основное действие очевидным, показывать реальный прогресс и полезную причину ошибки, иметь полноценную идентичность в панели задач/трее. Текущие формы/табличные размеры подлежат пересмотру, а не объявлены финальным дизайном.
